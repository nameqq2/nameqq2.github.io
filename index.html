                                                                                                                  岗位介绍

                                                                                                                  AI岗位为近两年比较热门且快速兴起的新岗位，在本人看来，该岗位为AI冲击下的【新后端】，区别于传统后端，该岗位不仅要求掌握后端开发的技术，在此基础上还要掌握智能体（即agent）方面的内容。

                                                                                                                  后端技术栈和相关学习概念

                                                                                                                  作为AI背景下的【新后端】，传统后端的技术栈还是需要掌握的。本人开发语言为python，python程序员可以参考一下。如果你是学java的，可以在java的基础上补充，毕竟有些服务还是通过python来搭建更方便一些。

                                                                                                                  一、后端框架

                                                                                                                  在 Python 后端框架中，FastAPI 是当前最主流的选择，选FastAPI就对了。对比常见的几个框架：

                                                                                                                  • 异步原生支持：处理高并发 I/O 任务时，不会像 Flask 那样的同步阻塞，“一个人干活，其他人排队”

                                                                                                                  • 自动生成 API 文档：运行起来后访问 /docs 就能看到 Swagger 风格的交互式文档，参数、请求体、响应格式一目了然，无需手动维护

                                                                                                                  • 基于类型提示的参数校验：用 Python 的类型注解写参数，FastAPI 自动帮你做类型转换和校验，无效请求直接挡在门外

                                                                                                                  二、数据库以及相应中间件

                                                                                                                  也就是传统后端学的sql语句和一些对应的中间件

                                                                                                                  关系型数据库

                                                                                                                  MySQL 是一个关系型数据库管理系统 (RDBMS)，基于表格存储数据，使用 SQL 进行查询。主要是做数据存储。

                                                                                                                  可视化的可以再安装一个phpmysqlAdmin，提供一个界面可以直接看到数据库的信息，同时也能在上面直接修改，删除，更新，还有执行sql。

                                                                                                                  现在都不用直接写sql（也不建议）来操作数据库，常用的是SQLAlchemy。SQLAlchemy 是 Python 中最著名的 ORM（对象关系映射） 框架，它允许你用 Python 类和对象 来操作数据库，而不是直接编写 SQL 语句。ORM 本质是将数据库的表映射为 Python 类，将表中的行映射为类的实例，将SQL 操作映射为对象的方法调用。

                                                                                                                  键值存储缓存数据库

                                                                                                                  Redis 是一个基于内存的键值 (Key-Value) 存储系统，通常被称为数据结构服务器。主要是做缓存使用的。

                                                                                                                  它们如何一起工作？

                                                                                                                  在实际生产系统中，两者通常配合使用：

                                                                                                                  1. 写入：数据先写入 MySQL（保证持久化和一致性），再更新或删除 Redis 中的对应缓存。

                                                                                                                  2. 读取：先查询 Redis；如果未命中，再去 MySQL 查询并回写 Redis，再返回结果。

                                                                                                                  3. 效果：既获得 Redis 的高并发低延迟，又保留了 MySQL 的数据安全和复杂查询能力。

                                                                                                                  这种模式被称为缓存旁路 (Cache-Aside)，是后端开发中最经典的数据访问模式之一。

                                                                                                                  Python 环境管理

                                                                                                                  一、为什么需要环境管理？

                                                                                                                  想象一下以下的场景：

                                                                                                                  项目 A 需要 Django 3.2，项目 B 需要 Django 4.2 ，但 同一个系统里装两个版本会冲突；你写代码时用 Python 3.10，服务器上是 Python 3.8 ，可能出现兼容性问题；pip install 装到全局，过一阵子自己都分不清哪个包是哪个项目用的

                                                                                                                  环境管理的核心目标：为每个项目创建独立的 Python 运行环境，互不干扰，可随时销毁重建。

                                                                                                                  三、conda

                                                                                                                  什么是 conda

                                                                                                                  conda 是一个跨语言的包管理和环境管理工具。最初为 Python 数据科学而生（Anaconda 发行版），现在也支持 R、Ruby、Lua、Scala、Java、JavaScript、C/C++ 等。

                                                                                                                  核心特点：

                                                                                                                  • 二进制包：不用本机编译，尤其适合 Windows 和复杂 C 依赖（如 NumPy、PyTorch）

                                                                                                                  • 跨语言：可以装 Python 包，也能装 CUDA 工具包、FFmpeg 等系统级工具

                                                                                                                  • 环境隔离彻底：每个环境有独立的 Python 解释器和完整目录结构

                                                                                                                  大模型概念

                                                                                                                  一、Transformer

                                                                                                                  这部分的内容老生常谈了，路边的阿猫阿狗都知道这玩意。这里就不做介绍误人子弟啦，推荐在B站或者抖音找视频看，基本都是很详细的，同时可以去看看《Attention Is All You Need》的原文品鉴一下。

                                                                                                                  2017 年，Google 的《Attention Is All You Need》论文提出了 Transformer 架构，彻底改变了游戏规则——摒弃循环，只靠注意力机制，让模型可以一次性看到整个句子中的所有词，并计算它们之间的关联程度。大模型时代（GPT、BERT、Llama、DeepSeek 等）的底层架构，全都是 Transformer。

                                                                                                                  二、MoE（混合专家模型）

                                                                                                                  MoE是当前超大模型（如DeepSeek、Mixtral、GPT-4）的核心技术之一。

                                                                                                                  MoE = 给大模型请了一群“专家”，每次只让最擅长的几个专家干活，而不是让所有参数都参与计算。

                                                                                                                  传统模型（稠密模型，Dense Model）处理每个Token时，所有参数都要参与计算——参数量越大，计算量越大。而MoE把模型分成多个“专家”（Expert），再配一个“门控网络”（Router/Gate），由门控决定每个Token应该交给哪几个专家处理。

                                                                                                                  核心概念

                                                                                                                  MoE的演进：从辅助损失到负载均衡

                                                                                                                  早期问题：门控网络总是倾向于把Token交给同一个最强的专家，导致专家“忙的忙死、闲的闲死”，效率低下。

                                                                                                                  解决方案：加入辅助损失（Auxiliary Loss，负载均衡损失）。在训练时惩罚专家使用的不均衡度，强制模型“均匀分摊任务”。

                                                                                                                  DeepSeek的创新：DeepSeek在V2版本中引入了更精细的负载均衡策略，包括专家级别的均衡和通信层面的优化，大幅提升了MoE的训练效率和推理速度。

                                                                                                                  典型MoE模型

                                                                                                                  MoE的优缺点

                                                                                                                  工程结论：如果你需要部署超大模型，MoE是绕不开的概念。DeepSeek就是靠MoE把API价格打下来的。但MoE的推理需要更多显存（因为要存放所有专家的参数，即使只激活一部分）。

                                                                                                                  补充：Mamba和RWKV是对Transformer的替代尝试，但目前尚未动摇Transformer的主流地位。如果你只做Agent/RAG开发，理解MoE就够了。

                                                                                                                  三、你需要知道的其他关键概念

                                                                                                                  训练阶段 vs 推理阶段

                                                                                                                  KV Cache

                                                                                                                  生成下一个Token时，之前Token的Key-Value向量可以复用，不用重新计算。这是推理加速的最重要手段。开启KV Cache后，长文本生成的吞吐量可以提升数倍。vLLM、SGLang等部署框架都深度优化了KV Cache的管理。

                                                                                                                  Flash Attention

                                                                                                                  让Attention计算变快、显存变少的关键技术。通过分块（Tiling）和重计算（Recomputation），将Attention的显存需求从O(N²)降到了O(N)。几乎所有现代部署框架（vLLM、Hugging Face的Transformers库）都内置了Flash Attention。

                                                                                                                  量化

                                                                                                                  一句话：用低精度数字（如INT8、INT4）代替高精度（FP16），牺牲少量精度换显存和速度。

                                                                                                                  在一些场景下，可能需要你去进行模型选项，考虑量化模型的情况。生产部署如果显存紧张可以用INT4。

                                                                                                                  四、大模型基础

                                                                                                                  大语言模型 (LLM)：GPT、Qwen、Llama、DeepSeek 等，擅长文本生成、理解、推理。

                                                                                                                  多模态大模型：能同时处理文本、图像、音频等。包括：

                                                                                                                  • VLM（视觉语言模型）：比如Qwen-VL，理解图像内容并回答文字问题。

                                                                                                                  • CLIP：计算文本与图像的相似度，用于零样本分类、检索。

                                                                                                                  OCR：光学字符识别（PaddleOCR、Tesseract），从图片中提取文字。

                                                                                                                  五、VLM（视觉语言模型）

                                                                                                                  VLM 是 Visual Language Model 的缩写，是一种能够同时处理图像和文本两种模态信息的大模型。它不仅能“看到”图片里的内容，还能理解这些内容与文字之间的关系，并用自然语言描述出来或回答问题。

                                                                                                                  还有用VLM做语义分割或者是示例分割的，感兴趣的可以去尝试了解一下

                                                                                                                  核心能力：

                                                                                                                  常见模型：

                                                                                                                  现在还是Qwen系列的模型用的比较多，毕竟一直在开源和更新

                                                                                                                  技术原理（简化版）：VLM = 视觉编码器 + 大语言模型。视觉编码器把图片变成一系列“图像特征向量”，大语言模型把这些特征当作“特殊词汇”来处理，从而同时理解文本和图像。

                                                                                                                  使用场景：

                                                                                                                  • 电商商品审核（图片 + 标题是否一致）

                                                                                                                  • 自动驾驶场景理解（识别路况并描述）

                                                                                                                  • 医疗影像辅助诊断（读片 + 生成报告）

                                                                                                                  • 图生文内容创作（根据产品图写营销文案）

                                                                                                                  六、CLIP

                                                                                                                  CLIP 是 Contrastive Language-Image Pre-Training（对比语言-图像预训练）的缩写，由 OpenAI 在 2021 年提出。它是一个图文双编码器模型，核心能力是把图像和文本映射到同一个“语义空间”中，然后计算它们的相似度。

                                                                                                                  核心原理：

                                                                                                                  CLIP 包含两个编码器：

                                                                                                                  • 图像编码器（Vision Encoder）：将图片转换成向量

                                                                                                                  • 文本编码器（Text Encoder）：将文字转换成向量

                                                                                                                  在训练时，CLIP 会学习让“配对的图文”（如一张狗的照片和文字“一只狗”）的向量距离尽可能近，让“不配对的图文”（如狗的照片和文字“一辆车”）的向量距离尽可能远。

                                                                                                                  核心能力：图文相似度计算

                                                                                                                  • 输入一张图片和一段文字，CLIP 输出一个相似度分数（0~1 之间）

                                                                                                                  • 分数越高，表示图文越匹配

                                                                                                                  # 伪代码示例

                                                                                                                  print(score)  # 0.92 表示非常匹配

                                                                                                                  七、Embedding（嵌入向量）

                                                                                                                  Embedding 是一种将离散数据（文字、图片、音频等）映射到连续向量空间的技术。简单说，就是把一个东西用一串固定长度的数字（比如 768 维的向量）来表示，使得语义相似的东西在向量空间里距离更近。

                                                                                                                  王后 = [0.6, 0.7, 0.2]
                                                                                                                  苹果 = [0.9, -0.2, 0.4]
                                                                                                                  

                                                                                                                  # 国王 vs 王后：向量距离近（语义相似）
                                                                                                                  # 国王 vs 苹果：向量距离远（语义不同）

                                                                                                                  • 做语义搜索（用文字搜文档）

                                                                                                                  ReAct Agent

                                                                                                                  ReAct 是 Reasoning（推理）和 Acting（行动）的缩写，结合推理 (Reasoning) 和行动 (Acting) 的范式。ReAct Agent 在一个循环中交替执行三个步骤：

                                                                                                                  1. Thought（思考）：模型分析当前状态，规划下一步要做什么，可能需要用到什么工具。

                                                                                                                  2. Action（行动）：模型输出一个具体的工具调用指令（如搜索、计算、调用 API），外部系统执行该指令并获得结果。

                                                                                                                  3. Observation（观察）：将工具执行的结果反馈给模型，作为下一轮思考的依据。

                                                                                                                  重复上述过程，直到模型认为任务已完成，输出最终答案。

                                                                                                                  以下是一个简单的天气调用例子：

                                                                                                                  Thought: 用户想知道今天北京的天气，我需要调用天气API。 Action: get_weather(city="北京") Observation: {"temp": 28, "condition": "晴", "humidity": "60%"}

                                                                                                                  Thought: 我已经获得了天气数据，可以回答用户了。 Final Answer: 今天北京天气晴朗，气温28°C，湿度60%。

                                                                                                                  Tool Use / Function Calling

                                                                                                                  是大模型原生支持的一种能力，但是在进行模型选项的时候要注意，有些模型是不支持Tool Use的。模型输出一个符合预定义 JSON Schema 的工具调用指令，而不是自由文本。这是实现 ReAct 中 Action 步骤的标准方式。

                                                                                                                  以下是工作原理和流程：

                                                                                                                  工作原理

                                                                                                                  1. 注册工具：开发者向模型声明可用的工具列表，每个工具包括名称、描述、参数（JSON Schema 格式）。

                                                                                                                  2. 模型推理：用户提问后，模型判断是否需要调用工具。如果需要，它不直接输出自然语言回答，而是输出一个结构化的 JSON 对象，指明要调用的工具和参数。

                                                                                                                  3. 外部执行：应用层解析该 JSON，调用对应的函数/API，获得结果。

                                                                                                                  4. 再次调用：将工具执行结果以普通消息形式返回给模型，模型继续处理（可能再调用工具，或生成最终答案）。

                                                                                                                  示例（OpenAI 风格）

                                                                                                                  工具定义：

                                                                                                                  python

                                                                                                                  xxxxxxxxxx

                                                                                                                          "parameters": {
                                                                                                                              "type": "object",
                                                                                                                              "properties": {

                                                                                                                              },
                                                                                                                              "required": ["city"]
                                                                                                                          }
                                                                                                                      }
                                                                                                                  }]

                                                                                                                  MCP（Model Context Protocol）：工具调用的标准化协议

                                                                                                                  MCP 由 Anthropic（Claude 的母公司）于 2024 年底提出，是一套旨在统一大模型与外部工具/数据源交互方式的开放协议。可以理解为 AI Agent 领域的“USB 接口标准”。

                                                                                                                  为什么需要 MCP？

                                                                                                                  在没有 MCP 之前，每接入一个工具（如数据库、GitHub、文件系统），开发者都需要：

                                                                                                                  • 为该工具编写专门的调用代码

                                                                                                                  • 定义 Function Calling 的 JSON Schema

                                                                                                                  • 处理认证、错误重试、流式响应等底层细节

                                                                                                                  这导致工具接入成本高，且无法跨模型复用。MCP 将这一过程标准化。

                                                                                                                  这一部分的概念很多，难免会看得有点烦燥,可以大概理解成一种规范化的协议。

                                                                                                                  MCP 的核心组件

                                                                                                                  工作流程

                                                                                                                  1. 用户配置 MCP Server 地址（例如本地运行的一个 weather-server 进程）。

                                                                                                                  2. MCP Host 启动时，向 Server 发送 tools/list 请求，获得该 Server 提供的所有工具及其参数描述。

                                                                                                                  3. Host 将这些工具统一转换为自己模型的 Function Calling 格式。

                                                                                                                  4. 当模型决定调用某个工具时，Host 通过 MCP 协议向 Server 发送 tools/call 请求。

                                                                                                                  5. Server 执行工具并返回结果，Host 将结果再喂给模型。

                                                                                                                  Skill：从文档到可执行模块

                                                                                                                  在实际工作中就是到处找各种好用的Skills让AI帮我们干活更好的提效，或者是自己做着玩（不是

                                                                                                                  定义：Skills是将特定任务的方法论、执行逻辑与资源封装成模块化单元，使AI能够按照预设流程执行复杂任务。它类似于人类的“技能”，即执行某件事的方法论。

                                                                                                                  Skills的组成与特点

                                                                                                                  组成：

                                                                                                                  • 元数据（Metadata）：包含对技能的简短描述，保存在全局上下文中，体积小，节省Tokens。

                                                                                                                  • 行动指南（Action Guide）：规定AI每一步该怎么做，是真正的提示词部分。

                                                                                                                  • 资源文件（Resources）：可能包含Python代码或其他执行程序，保证程序在调用Skill时能完成复杂的动作。

                                                                                                                  特点：

                                                                                                                  • 模块化与可复用性：Skills是模块化的能力单元，可以像积木一样组合使用，提高开发效率。

                                                                                                                  • 全局通用性：可以设置成项目级别或全局通用，避免每次聊天都复制长长的提示词。

                                                                                                                  • 能力扩展性：允许加入代码附件，极大地扩展了AI的能力边界，使其能够处理表格、批量重命名、自动化绘图等复杂任务。

                                                                                                                  二、RAG（检索增强生成）

                                                                                                                  说实话，RAG真的是大模型绕不开的一个话题了，基本接触大模型和智能体或者是想走这方面的同学应该第一步就是在接触和学习RAG吧，这东西说简单也很简单，但是说复杂的话整个流程还是需要很细致的处理的，网上找了一张图，可以参考一下

                                                                                                                  先对知识文本进行切分（可以是很多切分方法，这里不做展开）然后经过embedding模型向量化以后存入向量数据库Milvus/Faiss中。用户提问时，再对用户输入做一次向量化得到问题向量，随后在向量数据库中进行检索召回得到相似度最高的文本片段后返回给到大模型，再由大模型输出最终结果。这就是最简单的流程RAG流程了

                                                                                                                  但实际用起来流程没有那么简单，因为要追求召回的正确率和准确程度。在流程中还会添加【问题重写】，【重排序（Rerank）】等，下面开始介绍。

                                                                                                                  切块方式（Chunking）

                                                                                                                  切块是RAG的第一步，核心目标是将长文本拆解为适合检索的语义单元，既要避免信息过载，又要防止语义断裂。下面介绍一些常用的常见的切块方式。

                                                                                                                  固定长度切块（带重叠）

                                                                                                                  原理：不管语义，每N个字符切一刀。为了补救语义断裂，相邻块之间保留一部分重叠文字（如块大小500字符，重叠50-100字符）。

                                                                                                                  • 优点：实现简单，块大小完全均匀

                                                                                                                  • 缺点：极易切断语义，可能把专业术语拆碎或者是把句子直接截断

                                                                                                                  • 适用场景：日志文件、结构化数据

                                                                                                                  递归字符分块

                                                                                                                  由Langchain提供的切分策略，大致原理：先尝试按大段落（\n\n）切，不行再按换行（\n）切，还不行按空格切，最后按字符切。

                                                                                                                  举个例子：

                                                                                                                  想象一下，我们自己是如何阅读和拆分一篇长文的？我们通常会：

                                                                                                                  先看段落，尝试按段落分开。

                                                                                                                  如果一个段落太长，我们会再去看里面的句子，尝试按句号、问号等标点来切分。

                                                                                                                  如果一个句子还特别长（比如一个超长的法律条文），我们可能会再按短语（比如逗号、分号）来切分。

                                                                                                                  实在不行，最后才会按单词或字符来“暴力”拆分。

                                                                                                                  它维护一个分隔符列表 (separators) ，默认情况下是 ["\n\n", "\n", " ", ""]。

                                                                                                                  \n\n (双换行符)：代表段落。

                                                                                                                  \n (换行符)：代表行。

                                                                                                                  (空格)：代表单词。

                                                                                                                  "" (空字符串)：代表字符。

                                                                                                                  递归在这里体现：它会优先尝试用列表中的第一个分隔符（\n\n）进行分割。如果分割后的文本块仍然大于我们设定的 chunk_size，它就会“递归地”进入下一层，用第二个分隔符（\n）对这个过大的块进行再分割，以此类推，直到切分出的文本块小于 chunk_size 为止。

                                                                                                                  语义切块

                                                                                                                  用嵌入模型计算句子之间的语义相似度，在语义变化较剧烈的位置进行切分。计算句子向量后，检测相邻句子向量之间的向量距离，距离突增的地方就是语义边界。我自己是没试过的，这方式成本太高了，有需要的可以试着在自己电脑部署一个小参数的embedding模型来做

                                                                                                                  • 优点：效果最好，最大化保持语义完整性

                                                                                                                  • 缺点：计算成本高，需要引入额外的嵌入模型推理

                                                                                                                  • 适用场景：对检索质量要求极高的场景

                                                                                                                  父子块切块

                                                                                                                  这个在Dify自带的的知识库就有，作为一个切块选项可以选，原理是：检索时用小粒度块保证命中率，但返回给大模型时用大粒度块保证上下文完整。该方式会将同一段原文按不同的粒度拆分，父块是较大的文本块，保留有较为完整的上下文信息。子块是在父块的基础上进一步切分得到的更小的文本块，用于检索。

                                                                                                                  在实际索引时，只对子块建立向量索引；但在检索时，如果某个子块被命中，系统会将包含该子块的完整父块返回给大模型作为上下文。

                                                                                                                  • 优点：检索精度高，上下文完整，可调整父块和子块的大小与切分方式。

                                                                                                                  • 缺点：索引存储翻倍，因为需要同时存子块向量和父子映射关系）；切分逻辑较复杂因为需要维护层级结构； 检索延迟略高（多一次映射查询）

                                                                                                                  • 适用场景：长文档问答（技术手册、论文、合同）、需要保留逻辑因果关系的场景、对答案质量要求高于实时性的应用。

                                                                                                                  三、知识图谱：从实体关系到 GraphRAG

                                                                                                                  知识图谱是一种用图结构来组织知识的方式，将原本散落的信息通过实体和关系连接起来，形成一个可推理的知识网络。在 RAG 系统中引入知识图谱，可以让 AI 从"找到相关片段"升级为"理解事物之间的关联"。

                                                                                                                  基本结构

                                                                                                                  知识图谱由三个核心要素构成：

                                                                                                                  • 实体（Node）：现实世界中的对象，如人、公司、产品、概念。图谱中的每个圆圈就是一个实体节点。

                                                                                                                  • 关系（Edge）：实体之间的连接，描述它们如何关联。比如"张三 - 就职于 - 阿里云"。

                                                                                                                  • 属性：附着在实体或关系上的键值信息，如实体的名称、创建时间、描述等。

                                                                                                                  这种结构天然适合存储和查询具有复杂关联性的数据——传统的表格需要多表 JOIN 才能表达的连接关系，在图谱中就是一条直接的边。

                                                                                                                  Neo4j：图数据库的行业标准

                                                                                                                  Neo4j 是目前最流行的图数据库，使用 Cypher 作为查询语言（一种类似 SQL 但专为图设计的声明式语言），在这里不做展开，有需要的话可以自行去学习。

                                                                                                                  这东西学起来也挺麻烦的，不常用的话很容易忘记，我都是靠AI写。Neo4j2支持向量检索，我现在就用的Neo4j2

                                                                                                                  Tool（工具）的实现

                                                                                                                  工具（Tool）是 Agent 与外部系统交互的桥梁，让 Agent 能够执行实际的操作——查询数据库、调用 API、进行计算等。在 LangChain 中，工具本质上是被包装成统一接口的可调用函数。

                                                                                                                  使用 @tool 装饰器创建工具（最简单）

                                                                                                                  这是官方推荐的方式，函数名会自动成为工具名，docstring 会成为工具的描述，帮助 LLM 理解何时使用该工具。

                                                                                                                  参考代码如下：

                                                                                                                  xxxxxxxxxx
                                                                                                                  from langchain.tools import tool
                                                                                                                  

                                                                                                                  @tool
                                                                                                                  def search_database(query: str, limit: int = 10) -> str:
                                                                                                                      """Search the customer database for records matching the query.
                                                                                                                      
                                                                                                                      Args:
                                                                                                                          query: Search terms to look for
                                                                                                                          limit: Maximum number of results to return
                                                                                                                      """
                                                                                                                      # 模拟数据库查询
                                                                                                                      return f"Found {limit} results for '{query}'"
                                                                                                                  

                                                                                                                  # 查看工具属性

                                                                                                                  需要自定义函数名称和描述，可以用如下的写法：

                                                                                                                  xxxxxxxxxx
                                                                                                                  from langchain.tools import tool
                                                                                                                  

                                                                                                                  @tool("web_search", description="Search the web for real-time information")
                                                                                                                  def search_web(query: str) -> str:
                                                                                                                      """Search the web."""
                                                                                                                      return f"Search results for: {query}"
                                                                                                                  

                                                                                                                  print(search_web.name)  # web_search
